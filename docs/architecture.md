# QuantEvo Skill 架构与实施路线

项目名称：QuantEvo Skill。独立于私有 QuantEvo 仓库。
公开仓库：[EthanAlgoX/QuantEvo-Skill](https://github.com/EthanAlgoX/QuantEvo-Skill)。

## 产品目标

用户配置自己的 Codex 或 Claude Code → 安装技能 → 提供策略和行情 →
回测 → AI 提出候选 → 程序评测并记录 → 固定候选版本 → 前向模拟 →
在本地网站查看账户。AI 推理沿用宿主工具，无需在网站再配 LLM API。

## 职责

| 层 | 职责 |
| --- | --- |
| Skill | 收集任务约束、提出假设、调用工具、解释证据 |
| Python 引擎/CLI | 策略校验、数据校验、撮合、指标、研究规则和版本记录 |
| 模拟 Worker | 行情事件、账户状态、重启恢复和前向执行 |
| 本地网站 | 研究结果、净值、仓位、成交与数据新鲜度 |

首版工具随 skill 分发。研究及模拟规模增加后可扩展独立 Python 包与服务，
CLI 和网站调用同一应用层。MCP 属于可选入口，不是首版安装前置条件。

## 当前状态

已实现：标准技能目录、Codex/Claude 安装脚本、独立 JSON/CSV SMA 回测、
手续费/滑点、输入与引擎哈希、JSON 结果、合成测试数据。v0.1.0 已增加
追加 CSV 前向模拟、SQLite 多账户、固定策略与运行代码、后台进程、重启恢复、
本地双语只读网站与 JSON 检测接口。

尚未实现：持久化研究与实验预算、内置时间分割、留出最终检查、任意代码
策略接口、内置市场 API 数据源、OS 开机服务、无人值守的宿主 AI 调度。
`doctor` 的机器可读状态须随真实能力更新。

## 演进顺序

1. 基础验证：安装后从任意目录回测示例，确认不依赖私有项目或 LLM API。
2. 研究服务：固定评测合同、基线、逐轮 proposal/result、选择与最终检查，
   支持中断恢复和实验预算；把宿主 AI 接入提案接口。
3. 前向模拟：追加 CSV、固定版本与持久化账户已实现；后续接公开行情源。
4. 监控网站：模拟净值、持仓、成交和运行健康已实现；后续展示持久化研究记录。
5. 发行完善：选定许可证、完善英文与中文使用说明、干净环境集成验证，
   再发布版本；公开仓库已创建，正式许可证尚未确定。

## 策略与评测边界

首版示例支持 sma_cross 参数配置，使用简单均线，与旧项目 EMA 引擎不同。
这提供独立安装验证，不代表已经移植旧项目回测口径。
未来先实现明确的策略接口，再支持逻辑级变更；任意上传代码需要受控执行。
策略代码、评测引擎和评测合同各有版本，研究只能修改获准的策略部分。

历史回测、历史回放和前向模拟分别标记。研究未通过也应保存完整结果。
前向观察可以触发新研究，候选不能在后台悄悄替换模拟账户的版本。
多次研究同一时段应累计披露检查历史，不能重新宣称盲测。
